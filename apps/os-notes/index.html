簡答題的寫法

四題參考解答的結構都一樣，照這個順序寫就不容易漏：

第 1 章

認識電腦系統

電腦的硬體是固定的，「換程式就換功能」。作業系統是夾在硬體和使用者中間、讓兩邊好溝通的那一層。

馮紐曼與「儲存程式電腦」 影片 1-2

John von Neumann（馮紐曼）在 1945 年提出儲存程式電腦 stored-program computer：把程式和資料一起存在記憶體裡，硬體不用改，換一個程式就能做不同的事。這種電腦也叫 von Neumann machine 或通用型電腦 general-purpose computer。

廚房比喻

同一個廚房、同一個主廚，換一本食譜就能做出完全不同的菜。廚房（硬體）不用重蓋。

電腦系統的四個部分 影片 1-3

從上到下一層一層疊起來，上層用下層提供的功能：

使用者users
應用程式application program
作業系統operating system
硬體hardware

作業系統和組譯器、連結器、載入器、編譯器一樣都是「系統程式」，但作業系統要綜理整台電腦的資源，範圍比其他系統程式大得多。

程式從原始碼到跑起來的四個步驟 影片 1-5

  1. 編譯 compiling

    把人看得懂的程式碼（C、C++）翻成目的碼 object code。

  2. 連結 linking

    把好幾個目的檔和函式庫 library 接成一個執行檔。

  3. 載入 loading

    把硬碟上的執行檔搬進記憶體（RAM）。

  4. 執行 executing

    CPU 一條一條讀指令開始運算。

考試陷阱

題目常問「原始程式處理時，下列哪一道程序會先發生？(a) 執行 (b) 連結 (c) 載入 (d) 復原」。答案是 (b) 連結，因為順序是編譯→連結→載入→執行，選項裡最前面的是連結；「復原」不在這個流程裡。

RISC 和 CISC

CISC 複雜指令集

complex instruction set computer早期的設計。指令多、長度不固定，一個指令做很多事，常要好幾個時脈週期才做完。

RISC 精簡指令集

reduced instruction set computer1979 年 David Patterson 提出。指令長度與格式固定、多半一個指令週期就完成，方便管線化 pipeline、省電。

為什麼會有 RISC：大家發現常用的指令只佔約 20%，卻佔了程式的 80%。所以硬體專心把常用指令做快，複雜的指令就用簡單指令組合。

其他小觀念

  • 字元編碼 影片 1-2：電腦只認得 0 和 1，所以每個字元要對應到一組固定位元。ASCII（英文）、EBCDIC（IBM 大型主機）、Unicode（涵蓋全世界文字，包括中文）的對應方式不同。
  • 電腦的種類 影片 1-4：大型主機 mainframe、工作站 workstation、個人電腦、PDA、智慧型手機。手機和 PDA 也有 CPU 和記憶體，一樣算電腦，只是螢幕小、以觸控輸入為主。
  • 最貴的零件：CPU、記憶體、主機板。

第 2 章

作業系統面面觀

作業系統是「管資源的經理」，目標有兩個：讓電腦更好用（提供介面），讓電腦跑得更有效率（管好資源）。

作業系統的四大管理 影片 2-1

處理器管理、記憶體管理、檔案管理、裝置管理。「人員管理」不是作業系統的工作，考題常拿它當錯誤選項。

作業系統的演進 影片 2-1

第 1 代・1945–1955
真空管電腦，還沒有作業系統
第 2 代・1955–1965
電晶體，出現批次系統
第 3 代・1965–1980
積體電路，多重程式、分時系統
第 4 代・1980 之後
個人電腦普及

更早的前身是 19 世紀 Babbage 設計的差分機 difference engine。

資源共用的兩種方式 影片 2-1

時間多工

time-multiplexed按時間切，大家輪流用。
例：每個處理元輪流用 CPU 一小段時間。

空間多工

space-multiplexed把資源切成好幾塊，各用各的。
例：記憶體分成很多區，分給不同處理元。
廚房比喻

時間多工：主廚只有一個，每道菜炒一下就換下一道，輪流來。空間多工：料理台很大，切成幾塊，每道菜各佔一塊。

處理器模式：核心模式和使用者模式 影片 2-1、3-3

CPU 執行的工作有的來自作業系統，有的來自一般使用者，兩者權限不同，所以 CPU 有兩種模式：

  • 核心模式 kernel mode，也叫監督者模式 supervisor mode：作業系統最重要的功能在這裡執行，權限最大、限制最少，電腦完全信任它。這些功能就是作業系統的核心 kernel。
  • 使用者模式 user mode：一般程式在這裡執行，限制比較多，避免它弄壞系統。

一般程式要用到硬體或系統資源時，要向核心「申請」，方式有系統呼叫 system call 或訊息傳送 message passing。

廚房比喻

經理有倉庫的萬能鑰匙（核心模式）。一般員工（使用者程式）要拿倉庫的東西，得填單請經理拿（系統呼叫），不能自己進去翻。

第 3 章

認識處理元

程式是放在硬碟上的食譜，處理元是正在照食譜做的那道菜。作業系統用 PCB 這張工單，記住每道菜做到哪裡。

程式和處理元的差別 影片 3-1

程式 program處理元 process
是什麼存在硬碟上的可執行檔執行中的程式 program in execution
狀態靜態，不會動動態，記憶體內容隨著指令執行不斷變化
數量關係同一個程式可以同時跑成好幾個處理元（開兩個記事本視窗就是兩個處理元）。反過來一個處理元不會對應到多個程式檔。
  • 處理元是電腦系統中進行運算的基本單元（不是程式、檔案或資料夾）。
  • 中文名稱很多：處理元、行程、程序，英文都是 process。
  • 想看電腦裡有哪些處理元：Windows 開「工作管理員」，UNIX 用 ps 指令。

blocked → ready等的事件完成了，回去排隊等 CPU烤箱好了，回到排隊區
running → done執行完畢出餐
考試陷阱

「ready → done」不存在。就緒的處理元還沒開始跑，不可能直接完成。另外注意 blocked 不能直接回 running，要先回 ready 排隊。

PCB：處理元控制方塊 影片 3-4

作業系統替每個處理元準備一張「工單」，叫 PCB Process Control Block，作業系統就是用 PCB 這種資料結構來表示一個處理元。處理元要被載入、準備執行之前，就要先用 PCB 記下它的資訊。PCB 裡面有：

  • 處理元狀態 process state：現在是 ready、running 還是 blocked
  • 程式計數 program counter：下一個要執行哪一行指令
  • CPU 暫存器 CPU registers：上次暫停時 CPU 裡的內容
  • 處理元排程資訊：優先順序 priority 就記在這裡
  • 記憶體管理資訊：它用了哪些記憶體
  • 使用統計資訊 accounting information：用了多少 CPU 時間等
  • I/O 狀態資訊 I/O status：開了哪些檔案、用了哪些裝置
廚房比喻

主廚炒到一半被叫去做別道菜，回來時要知道「剛剛做到第幾步、鍋裡放了什麼」。PCB 就是那張寫著進度的工單，換菜時寫下來，回來時照著接續。

考試陷阱

PCB 不等於處理元的影像 process image。影像是「程式＋資料＋系統堆疊＋PCB」全部加起來，PCB 只是其中一部分。考題「PCB 也就是處理元的影像」是錯的。

  2. 同一個處理元裡的執行緒之間切換 switch 很快。
  3. 同一個處理元的執行緒互相溝通不用核心 kernel 插手，效率高。

第 4 章

CPU 排程

好幾個處理元都想用 CPU，排程就是決定「誰先用、用多久、什麼時候換人」。

為什麼要排程 影片 4-1-1

多工作業系統會同時把好幾個處理元放進記憶體，用時間多工的方式共用 CPU。另一個重點是：正在等 I/O 的處理元要先讓出 CPU，不然 CPU 會閒著沒事做。不排程的話，資源使用就會一團亂。

排程的「政策」和「機制」 影片 4-1-2

政策（策略）

policy / strategy決定處理元使用 CPU 的順序：下一個該誰？

機制

mechanism決定CPU 配置給處理元的方法：實際把目前的處理元移出 CPU、把下一個移進去。
廚房比喻

政策是經理決定「先做 3 號桌再做 5 號桌」；機制是實際把鍋子從爐上拿下來、換下一鍋上去的動作。

考試陷阱

「排程的政策決定處理元使用 CPU 的時間長短」是錯的。政策決定的是順序。

可間斷和不可間斷 影片 4-1-3、4-1-4

不可間斷（非搶占）

nonpreemptive拿到 CPU 的處理元會一直執行到結束（或自己去等 I/O），中間不能被打斷。

可間斷（搶占）

preemptive用間隔計時器 interval timer 限制每個處理元能佔用 CPU 多久，時間到或有更高優先權的來，就把 CPU 重新分配。

三種時間（必考定義） 影片 4-1-2

名稱課本定義白話

等待時間

多處理器的排程 影片 4-2

這是講解目次第 4 章的第二個重點。單處理器只要決定「下一個誰用 CPU」；多處理器有好幾顆 CPU，還要決定誰用哪一顆，必須考慮多顆 CPU 同時運作的情況，所以比單處理器複雜。

一般教科書會提到的考量：讓每顆 CPU 的工作量差不多（負載平衡）；處理元盡量留在同一顆 CPU 上執行，比較能利用那顆 CPU 的快取。

課堂例題：算平均輪轉時間與平均等待時間 影片 4-1-3

5 個處理元 P1～P5 依序進入 ready list，服務時間分別是 300、150、430、230、92。切換看看兩種排法：

處理元服務時間 L等待時間 W（＝開始時間）輪轉時間 T（＝完成時間）

解題步驟
  1. 照排程法決定順序（FCFS 照到達順序，SJN 從短排到長）。
  2. 第一個處理元：等待 0，輪轉時間＝自己的服務時間。
  3. 之後每一個：等待時間＝前一個的輪轉時間；輪轉時間＝自己的服務時間＋前一個的輪轉時間。

第 5 章

處理元同步

好幾個處理元同時搶用同一份資料時，要定好規矩「一次只准一個進去」，不然結果會亂掉。

什麼是同步 影片 5-1-1

同步 synchronization / concurrency：多個處理元同時在執行、輪流用 CPU，需要互相協調。這不是作業系統才有的問題，生活中也有：配音和影片要對嘴、芭蕾舞者要跳得一致、分散在各地的資料庫資料要一致。多工作業系統本來就允許多個處理元同時執行。

臨界區域 critical section 影片 5-1-2

兩個處理元共用同一個變數時，各自使用這個變數的那段程式就叫臨界區域。如果不控制，兩個同時跑，每次結果可能都不一樣（non-determinate）。例子：

時間處理元 A（領 100 元）處理元 B（領 100 元）帳戶餘額
1讀到餘額 10001000
2也讀到餘額 10001000
3寫回 1000－100＝900900
4寫回 1000－100＝900900（應該是 800！）

解決原則：互斥 mutual exclusion，任一處理元進入臨界區域時，其他處理元就不能同時進入自己的臨界區域。作業系統提供的工具就是下面的號誌和監督器。

號誌 semaphore 影片 5-3

號誌是一個受保護的整數，只能用兩個不可分割的動作來改它。補充講義把它比喻成停車場的空位計數器：

P 操作

P() / wait()要使用資源時做。號誌 > 0 就減 1 進去；等於 0 就得排隊等。

V 操作

V() / signal()用完、釋放資源時做。號誌加 1，並叫醒正在等的處理元。

記法：字母順序 P 在 V 前面，進去前先 P，出來後才 V。

動手試試：3 個車位的停車場 號誌 S ＝ 3
門口排隊中：

按「來一台車」看看。車位滿了以後再來的車要在門口等，直到有車開走（V）。

監督器 monitor 影片 7-3

號誌很好用，但問題一複雜，P、V 的位置很容易寫錯。監督器是更高階的寫法：把共享變數、操作它的程序，以及同步機制包在一起（抽象資料型態）。

  • 自動互斥：任何時間只有一個處理元能在監督器裡執行程序，其他的自動在外面排隊。
  • 條件變數 condition variables：搭配 wait() 和 signal()，讓處理元在某些條件下（例如緩衝區滿了）暫停或被叫醒。
  • 能力一樣：號誌和監督器能解決的問題一樣多，只是監督器用起來簡單多了。
比喻

號誌：門口掛著空位牌，每個人要自己記得進門翻牌、出門翻回來，有人忘了就出事。監督器：包廂門口站著一位服務生，一次只放一個人進去，你不用自己管牌子。

經典同步問題

  • 讀者與寫者問題 readers-writers problem：很多人可以同時讀同一份資料，但有人在寫的時候，其他人不能讀也不能寫。
  • 哲學家用餐問題 dining philosophers problem 影片 5-4：Dijkstra 在 1965 年提出，同時示範同步和死結。

第 6 章

死結 deadlock

大家手上都抓著一樣東西，又在等別人手上的東西，而且誰也不放手，整個系統就卡死了。

廚房比喻

阿明拿著唯一的鍋子在等鏟子，阿華拿著唯一的鏟子在等鍋子。兩人都不肯先放手，也不能去搶對方的，兩道菜永遠做不完。

資源與死結的成因 影片 6-1

  • 實體資源：看得到摸得到的硬體，例如 CPU、記憶體、印表機。
  • 邏輯資源：軟體層面的東西，例如號誌、監督器、檔案。
  • 死結的主要原因：容許多個處理元同步執行（不是資源太多、電腦太慢或網路太複雜）。
  • 資源分配圖 → 等待圖 wait-for graph：把資源節點拿掉，只留「誰在等誰」。每種資源只有一個時，圖上出現環就代表死結；有多個同類資源（多個 instance）時，有環也不一定是死結。

四種處理死結的方法 期中考簡答 影片 6-2～6-5

方法做法比喻
預防
prevention
影片 6-2		讓四個條件無法同時成立，死結就不可能發生。例：規定開工前一次拿齊所有資源（破壞占有與等待）；資源編號、只能照順序拿（破壞循環等待）。規定每個廚師開工前要一次領齊鍋子和鏟子

「避免」和「預防」差在哪？

預防是事先立規矩，讓四個條件不可能同時成立；避免是不改規矩，但每次分配資源前先算會不會進入不安全狀態。

預防像「規定一次領齊工具」，避免像「銀行放款前先試算」。

置換作業 swapping 影片 8-3、11-4

記憶體不夠時，作業系統把暫時不會執行的處理元整個搬到硬碟上，騰出記憶體給需要的處理元；之後輪到它，再搬回記憶體。

廚房比喻

料理台滿了，經理把暫時沒在動的那盤（例如在等烤箱的）先收進冰箱，空出位置給要開始做的菜；等輪到它，再從冰箱拿出來。

虛擬記憶體：分頁法和分段法 影片 9-2、9-3

虛擬記憶體：只把正在用到的部分放進 RAM，其他先放在硬碟。好處是程式可以比 RAM 還大、記憶體用得更有效率、能同時跑更多程式。缺點是要用的部分不在 RAM 時，得停下來去硬碟拿，這叫分頁中斷 page interrupt / page fault，會有額外成本。

每頁一樣大，最後一頁通常裝不滿，黃色那段浪費在頁的「內部」→ 有內部碎片，沒有外部碎片。

需要多少給多少，沒有內部碎片；但段和段之間會留下零碎空洞 → 有外部碎片。

  • 內部碎片：分到的那塊比需要的大，多出來的浪費在那塊裡面。
  • 外部碎片：記憶體裡有很多小空洞，加起來夠用，卻沒有一塊連續的夠大。

磁碟 影片 11-1、11-2

  • 空間大小：磁盤 > 磁軌 > 磁區。
  • 磁柱 cylinder：好幾片磁盤疊在一起時，同一個位置的磁軌合起來。
  • CHS：用「磁柱、磁頭、磁區」三個數字找位置。
  • LBA logical block address：直接給每個磁區一個序號 0、1、2…，簡單很多。

磁碟排程：很多讀寫請求在排隊，磁頭要決定先去哪裡，目標是少移動。例：磁頭在 53，請求依序是 98、183、37、122、14、124、65、67。

平行與分散式系統

Flynn 分類：看「同時有幾道指令流」和「同時處理幾份資料流」。

單資料流多資料流
單指令流SISD：傳統單 CPU 個人電腦、大型主機SIMD：一道指令同時處理很多資料，陣列處理器 array processor、向量處理器

  • 分散式系統 影片 13-1、15-1（正式名稱 distributed computing system）：很多台獨立的電腦透過網路合作，對使用者來說看起來像一個完整的系統。它主要是軟體系統的概念，不是單純的硬體。
  • 網路作業系統 vs. 分散式作業系統 影片 13-1：網路作業系統裡，使用者知道有很多台電腦，要自己登入或存取遠端資源；分散式作業系統則把多台電腦包裝成好像只有一台。常見再加上建立在各機器作業系統之上的「中介軟體」middleware 做法。作業第 3 題請翻課本對照它列出的類型。

  • 網路檔案系統 影片 14-1、14-2：NFS（Sun 開發，常用於區域網路）；AFS（Andrew File System，為大規模、廣域網路設計）；Novell NetWare（區域網路的網路作業系統）；EFS 是 Windows 的加密檔案系統，不是網路檔案系統。
